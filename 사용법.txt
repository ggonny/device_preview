반응형 테스트랩

실행 방법
1. 압축을 푼 뒤 index.html을 브라우저에서 엽니다.
2. 테스트할 사이트 주소를 입력하고 ‘사이트 열기’를 누릅니다.
   (URL 을 입력하기 전에도 주소창 아래에 선택된 기기 프레임이 바로 표시되고, 기기 선택·접힘/펼침·회전·브라우저·가이드·배율을 모두 쓸 수 있습니다. 화면 안에는 "URL을 입력해 미리보기를 시작하세요." 자리표시 페이지가 들어 있습니다.
    주소창을 비우고 "사이트 열기"(또는 입력창의 × 지우기) 를 누르면 사이트만 내리고 현재 기기 프레임은 그대로 자리표시 페이지로 돌아갑니다.)
3. 왼쪽 기기 프리셋과 상단의 회전 버튼으로 화면을 확인합니다.
4. 브라우저 종류를 고르고 주소창·툴바 스위치로 실제 사이트 표시 영역을 비교합니다.
5. 로컬 파일 실행이 제한되면 VS Code Live Server로 폴더를 실행해 주세요.

    상단이면 상태바(노치·다이내믹 아일랜드·펀치홀 영역) 아래에서 시작하고, 하단이면 콘텐츠 아래·툴바 위에 놓입니다.
    가로 모드에서는 실제 브라우저처럼 상단에 고정됩니다.
  · 툴바 스위치: 하단 툴바 표시 여부
  · UI 겹침 스위치: URL 바·툴바가 사이트 영역을 줄이지 않고 콘텐츠 위에 겹침 (100vh 가림 확인)
- 상단 컨트롤은 기기 정보 → 화면 상태 → 화면 크기 → 브라우저 UI → 회전·배율 순서로 자리가 고정되어 있어
  접힘/펼침 기기를 선택해도 다른 컨트롤의 위치가 바뀌지 않습니다. (단일 화면 기기는 '단일 화면' 표시)
- 다중 비교 (왼쪽 상단 '단일 보기 / 다중 비교' 스위치)
  · 기기 목록이 체크박스로 바뀌며 최대 4개까지 선택할 수 있습니다. 체크를 해제하면 해당 카드만 사라집니다.
  · 카드는 CSS Grid(auto-fit) 로 폭에 따라 1~4열에 자동 배치되고, 좁은 화면에서는 다음 줄로 내려갑니다.
  · 공통 제어(모든 카드에 적용): URL 열기, 새로고침, 회전, 주소창·툴바·UI 겹침, 주소창 위치, safe-area 가이드, 배율.
    직접 크기 입력과 브라우저 종류 선택은 단일 보기에서 사용합니다(플랫폼별 브라우저 선택은 비교 카드에도 적용).
  · 카드별 제어: 기기명·사이트 크기 표시, 화면 상태(접힘/펼침 기기), 회전, 새로고침, 비교 목록에서 제거.
  · 동기화 옵션: 스크롤 / 회전 / 새로고침. 회전·새로고침 동기화를 끄면 카드 버튼이 그 카드에만 적용됩니다.
  · 스크롤 동기화는 scrollTop 을 그대로 복사하지 않고 각 문서의 스크롤 비율(scrollTop ÷ (scrollHeight − clientHeight)) 로 맞춥니다.
    → 뷰포트 높이가 다른 기기에서도 같은 콘텐츠 위치가 보입니다. 어떤 카드를 스크롤해도 나머지가 따라오고, 추가·새로고침된 카드는 현재 위치로 정렬됩니다.
  · 선택한 기기·상태·회전·동기화 옵션은 다시 열 때 복원됩니다.

스크롤 동기화 제한 (중요)
- 브라우저의 Same-Origin Policy 때문에 iframe 안 문서의 스크롤 위치는 이 도구와 프로토콜·호스트·포트가 모두 같은 페이지에서만 읽고 옮길 수 있습니다.
  · 가능: 도구를 http://127.0.0.1:5501 로 열고 http://127.0.0.1:5501/... 페이지를 불러온 경우
  · 불가: 외부 사이트(https://example.com 등), 다른 포트, localhost ↔ 127.0.0.1 처럼 호스트 표기가 다른 경우, 도구를 file:// 로 연 경우
- 불가능한 경우 스크롤 동기화 스위치가 비활성화되고 비교 바와 카드 배지에 이유가 표시됩니다. 우회 코드는 두지 않았습니다.
- 페이지 안의 별도 스크롤 컨테이너(overflow 요소) 는 동기화 대상이 아니며, 문서(window) 스크롤만 맞춥니다.
- 향후 Chrome Extension 으로 만들면 cross-origin 페이지도 동기화할 수 있습니다:
  content script 를 all_frames 로 각 iframe 문서 안에 주입하면 그 문서의 출처에서 실행되므로 scrollTop 읽기·scrollTo 가 가능하고,
  비율 값만 chrome.runtime 메시지로 도구 페이지(또는 background) 를 거쳐 다른 프레임의 content script 로 전달하면 됩니다.
  현재 app.js 의 getScrollRatio()/applyScrollRatio()/broadcastScroll() 이 그대로 content script 로 옮겨질 수 있는 구조입니다.

상태바·컷아웃·브라우저 UI 레이어
- 노치 / 다이내믹 아일랜드 / 펀치홀 = 기기 하드웨어(frameProfiles.cutout, .screen_cutout 레이어)
- 시간 / 셀룰러 / Wi-Fi / 배터리 = OS 상태바(statusBarProfiles: ios / android(표준 Android 기본값) / oneui(Galaxy) / generic(범용 프리셋), .band_status 레이어)
  · 프레임의 platform 으로 프로필을 고르고 frameProfiles[*].statusBar 로 항목을 덮어씁니다(예: iPhone SE 의 레거시 배치, Galaxy 의 oneui).
  · 아이콘은 자체 SVG(외부 라이브러리·제조사 이미지 없음) 이며 좌/우 정렬 컷아웃(Fold 펼침 카메라 등) 만큼 자동으로 비켜납니다.
  · 2026-09-21 전 기기 재실측: iPhone 은 Apple 공식 이미지(뉴스룸·HIG·지원 문서), Galaxy 는 Samsung 공식 렌더·실사진, Pixel 은 AOSP 값 기준으로 시간 크기·아이콘 크기·간격·좌우 여백·세로 위치를 맞췄습니다.
    iPhone 노치 기기는 시간이 노치 아래쪽(26pt), 아일랜드 기기는 아일랜드 세로 중앙에 놓이고, Galaxy(One UI 7 이후) 는 숫자가 든 알약형 배터리와 가는 4막대 신호 아이콘을 씁니다.
- Safari / Chrome 주소창·툴바 = 브라우저 UI(browserProfiles, .band_url / .band_toolbar 레이어)
- iPhone Duo(iOS 27) 는 위 가로 밴드 대신 다음 레이어를 씁니다 (Apple 뉴스룸·HIG "Designing for iPhone Duo" 기준):
  · 코너 상태 클러스터(statusBarProfiles.duo, layout:'corner', .status_cluster): 시간 → 아래가 트인 링(안쪽 Wi-Fi) → 링 틈의 셀룰러 점 4개.
    카메라 축(외부 48px · 내부 45px) 에 놓이며 값은 frameProfiles[*].statusBar 가 화면별로 지정. 링 호가 배터리 잔량인지는 미확인(고정 호, approximation).
  · 세로 Dynamic Island(.dynamic_island, OS UI): 외부 화면 카메라를 감싸는 세로 필 38×62 @ top 26 — 통화(Live Activity) 공식 이미지 실측.
    정지 상태(홈 화면 이미지·HIG 도식) 는 카메라 원만 보이며 statusBar.island.state:'rest' 로 바꿀 수 있습니다. 내부 화면은 카메라가 화면 뒤(UDC) 라 표시하지 않습니다.
  · Safari 측면 컨트롤(browserProfiles['duo-safari'], layout:'side', .side_controls): 클러스터 아래에 뒤로 원형(Ø44) + 캡슐(정보·공유·검색), 하단에 캡슐 4개.
    항목 형태·크기·간격은 뉴스룸 Split View 이미지 실측, 전체 화면 Safari 의 시작 높이는 Netflix 이미지의 시스템 간격(22) 준용(approximation).
    주소(URL) 필드는 공식 자료에 보이지 않아 그리지 않습니다("실제 Safari UI" 단정 아님). 주소창 스위치 = 위 그룹, 툴바 스위치 = 아래 캡슐, 주소창 위치 라디오는 잠김.
    사이트 뷰포트는 화면 전체(콘텐츠 위에 겹침) 이며 실제 Safari 의 인셋은 미확인 — safe-area 가이드로 측면 열 영역(우측 92/89px) 을 확인하세요.
  · 세로 공간이 부족하면(외부 화면 가로) HIG 대로 탭바가 단일 컨트롤로 접히고 툴바 항목은 넘침(…) 으로 들어갑니다.
  · 회전: 외부 화면은 카메라 쪽 가장자리를 따라 열이 왼쪽으로 이동(반시계 회전 기준). 내부 화면을 세로로 돌리면 HIG 대로 표준 가로 바(Safari 밴드 차용, 상태바 밴드 0) + 코너 클러스터(위치 approximation).
- safe-area 가이드: 노치·다이내믹 아일랜드·펀치홀·홈 인디케이터가 차지하는 영역을 빗금으로 표시
- 기기별 둥근 모서리, 홈 버튼, 노치, 다이내믹 아일랜드, 펀치홀, 커버 카메라, 접힘선, 홈 인디케이터 표시
- 프리셋별 전체 CSS 화면, 실제 사이트 표시 영역, 물리 해상도와 DPR 표시

표시 배율
- 배율은 기기 프레임 전체의 "보이는 크기" 만 바꿉니다. iframe 의 CSS 뷰포트, 미디어 쿼리 결과, DPR, 기기 프로필은 배율과 무관하게 그대로입니다.
- 100% = 기기 CSS 1px 을 PC 브라우저 CSS 1px 로 1:1 표시하는 배율입니다. 실제 기기의 물리 크기가 아닙니다.
- [−] / [+]: 현재 배율에서 5% 씩 줄이거나 키웁니다 (25%~200%). 숫자 칸에 % 를 직접 입력하고 Enter 하면 5% 단위로 반올림해 적용됩니다(↑/↓ 키도 5% 단위).
- 수동으로 정한 배율은 창 크기를 바꾸거나 기기를 바꾸거나 회전해도 그대로 유지됩니다.
- 화면 맞춤: 미리보기 영역에 기기 전체가 들어오도록 자동 축소하며, 창 크기·기기·회전이 바뀌면 다시 계산합니다.
- 실기기: 공개된 화면 크기(inch)와 CSS 화면으로 계산한 물리 크기 근사값입니다. 모니터 크기와 Windows 화면 배율에 따라 실제 기기 크기와 차이가 날 수 있습니다.

사이트 영역 계산
- 프리셋의 너비·높이는 기기 전체 CSS 화면입니다.
- 기본(축소) 모드: 상태바 + 주소창 + 툴바 + 홈 인디케이터 높이를 뺀 영역이 iframe 크기가 됩니다.
  → 실기기에서 브라우저 UI가 모두 보이는 상태(svh)에 해당합니다.
- UI 겹침 모드: 상태바·홈 인디케이터만 빼고 주소창·툴바는 콘텐츠 위에 겹칩니다.
  → 실기기에서 100vh가 큰 뷰포트(lvh) 기준으로 잡혀 하단 고정 요소가 URL 바에 가려지는 현상을 확인할 수 있습니다.
- 가로 모드에서 iOS Safari·Android Chrome은 컷아웃 쪽 safe-area만큼 사이트 폭이 줄어듭니다(기본 동작). 미리보기도 같은 폭으로 계산합니다.

확인 범위
- 브라우저 UI 높이는 Safari·Chrome·Samsung Internet의 일반적인 값을 바탕으로 한 근사치이며, 스크롤에 따른 자동 숨김은 구현하지 않습니다.
- 검은 노치·카메라·접힘선과 safe-area 가이드는 콘텐츠 위에 표시되어 가려지는 영역을 확인할 수 있습니다.
- iframe 안의 페이지는 env(safe-area-inset-*) 값을 받을 수 없습니다. 가이드와 겹치는 콘텐츠는 실기기에서 가려질 수 있습니다.
- 표시된 물리 해상도와 DPR은 기기 사양 정보이며 iframe의 실제 렌더링 DPR과 UA를 변경하지는 않습니다.
- 프레임과 가림 위치는 제조사 공개 사양을 바탕으로 한 시각적 근사치입니다.
- iframe에서 재현되지 않는 것: UA, 실제 DPR, 터치·hover·pointer 미디어, safe-area 환경변수, dvh/svh/lvh 단위, 대상 페이지의 <meta name="viewport"> 처리(비반응형 페이지가 980px로 축소되지 않음), 가상 키보드, 브라우저 자동 숨김, 실제 힌지·화면 분할 API.
- 스크롤바: URL 없는 자리표시 페이지와 이 도구와 같은 출처(같은 호스트·포트)의 페이지는 모바일처럼 스크롤바를 숨깁니다(스크롤바만 숨기고 휠·터치패드·키보드 스크롤과 스크롤 동기화는 그대로).
  다른 출처의 외부 사이트는 브라우저 보안 정책(Same-Origin Policy)상 iframe 안의 스크롤바 스타일을 제어할 수 없으므로, Windows 브라우저에서는 실제 iframe 의 데스크톱 스크롤바(약 17px)가 보이고 그만큼 콘텐츠 폭이 줄어들 수 있습니다. iframe 폭을 늘리거나 가장자리를 가리는 보정은 하지 않습니다(뷰포트 정확도 우선).
- 대상 사이트가 X-Frame-Options 또는 CSP frame-ancestors로 iframe 표시를 차단하면 미리보기가 비어 보일 수 있습니다.

기기 추가 방법 (app.js)
- devices 에 항목을 추가하면 사이드바·기기 수·WebMCP 도구 목록에 자동 반영됩니다.
  · group: deviceGroups 의 id (base / phone / fold / tablet)
  · frame: frameProfiles 의 키, browser: browserProfiles 의 키
  · states[]: width/height(CSS px), diagonal(inch), physicalWidth/Height(생략 시 width×dpr), 필요하면 frame/browser/hinge/orientation 오버라이드
- 새 컷아웃·safe-area가 필요하면 frameProfiles 에 프로필을 추가합니다. cutout.type 은 none / notch / island / hole / dual-hole.
  · 세로 위치는 top(위 가장자리 거리) 또는 bottom(아래 가장자리 거리, Flip8 커버처럼 카메라가 아래에 있을 때). 가로 모드는 반시계 회전(아래 → 오른쪽).
  · dual-hole 은 [플래시][렌즈][렌즈] 가로 상자: lens(렌즈 지름) / ring(링 두께) / lensGap / flash(플래시 지름) / flashGap. display.mask:'holes' 를 주면 디스플레이 마스크에서 렌즈·플래시 원이 빠져
    실제 가시 영역이 되고(콘텐츠가 렌즈 뒤로 가지 않음), 하드웨어(.screen_cutout) 는 마스크 바깥 레이어에 그려집니다.
- 기기 형상은 전부 frameProfiles 데이터로 정하며, 각 프로필의 source 메타데이터에 값의 근거 등급을 적습니다:
  · official       : 제조사 공개 수치 (해상도, 바디 mm, iOS safe-area 등)
  · derived        : 공개 수치에서 환산 (베젤 = (바디 − 활성영역)/2 → CSS px, 동심 가정 바디 코너 = 화면 코너 + 베젤 등)
  · photo-measured : 렌더 실측 (파일명·비율을 note 에 기록. Commons 벡터 "IPhone SE (2nd generation) white vector.svg", "IPhone 12 Blue.svg",
                     "Galaxy S25 Black (front).png", "Google Pixel 9 (Obsidian) front.svg", Apple 뉴스룸 "Apple-iPhone-Duo-display-sizes-260909.jpg",
                     samsung.com "galaxy-z-flip8-features-colors-design.jpg"(Flip8 접힘 정면), Samsung 뉴스룸 "...Launch_dl3F.jpg"(Flip8 펼침 상단부, 저해상도))
  · approximation  : 근거 없음 — 실제 사양처럼 취급하지 말 것 (Fold8 의 코너·컷아웃, Flip8 펼침 화면 코너·측면 키, Duo 의 접힘선 굵기·Safari 시작 높이·회전 시 클러스터 위치, Android 하단 제스처 바 등)
  · controls 필드(홈 버튼·스피커·카메라·센서) 는 CSS 변수로 그려지며 가로 모드는 반시계 규칙으로 옮겨집니다.
    camera/sensor 에 edge:'right'|'left' + offset(화면 중심에서 아래 +/위 −) 을 주면 긴 변 베젤(iPad Air·Galaxy Tab 처럼 가로 카메라) 에 놓이고, inset 으로 가장자리에서 중심까지 거리를 정할 수 있습니다.
    cutout 에 edge:'right'|'left' + depth/length/offset 을 주면 긴 변 컷아웃(Galaxy Tab S11 Ultra 의 완만한 노치, shape:'wave') 이 되며 가로에서는 상단 중앙으로 돌아갑니다.
    keys:[{type:'volume'|'power', edge, start, length}] 를 주면 family 기본 위치 대신 실측 위치에 키를 그리고(두 번째 volume 은 .key_volume_b), port:{edge,width,height} 는 USB-C 같은 커넥터 슬롯입니다.
  · 해상도는 세 층위로 적습니다: nativePhysicalResolution(제조사 표기 그대로, official) / renderedPhysicalResolution(세로 프리뷰 기준 width×height, derived-orientation) / cssViewport(DPR 가정 파생값, derived — 해당 모델 실기기에서 innerWidth·devicePixelRatio 를 직접 확인한 경우에만 verified. 전작·동일 패널 준용값은 derived).
- 기기 형상은 전부 frameProfiles 데이터로 정합니다 (CSS 에 기기명 분기 없음):
  · family: 형상 언어. iphone-modern / iphone-classic / galaxy-bar / fold / flip / duo / ipad-classic / ipad-modern / galaxy-tab / neutral
    → 바디 마감(금속 링 색·하이라이트·글래스 색), 측면 키, 스피커·홈 버튼 표시가 이 값으로 갈립니다. 새 마감이 필요할 때만 CSS 에 family 하나를 추가합니다.
  · top/right/bottom/left: 베젤 두께(바디 외곽 ~ 디스플레이). ring: 그중 금속 테 두께, 나머지는 검은 글래스로 그려집니다.
  · radius(바디) / screenRadius(디스플레이): 숫자(px) 또는 {ratio: 0.05}(짧은 변 대비) 또는 {tl,tr,br,bl}(코너별). 가로 모드는 코너를 반시계로 돌립니다.
  · display.split: 듀얼스크린(물리 분리 패널) 용 {axis, gap, panelRadius}. 현재 프리셋에는 없음(iPhone Duo 는 단일 폴딩 화면). Surface Duo 2 같은 기기를 추가할 때 사용.
  · hingeBody: 힌지 커버(바디·디스플레이·접힘선과 별개 요소). {type:'spine', side, width, inset, radius} = 접힌 북타입에서 패널 바깥 힌지 쪽에 보이는 스파인,
    {type:'seam', size} = 펼침 상태에서 접힘선 양끝 테두리의 접합선. 가로 모드는 반시계 규칙으로 옮겨집니다(left → bottom).
  · 레이어 순서: 바디(금속 링) → 힌지 커버(.hinge_body, 바디 바깥) → 글래스 베젤 → 디스플레이 마스크(.screen_wrap: 상태바·브라우저 UI·사이트·접힘선이 모두 이 안에서 clipping) → 하드웨어 컷아웃(.screen_cutout, 마스크 바깥 셸 직계 자식).
  · Galaxy Z Flip8 커버 화면: 힌지가 위, 카메라 2개 + 플래시가 우하단에 화면 안 홀로 있고, 콘텐츠·브라우저 UI 는 카메라 위에서 끝납니다(하단 내비게이션 밴드 72px, 공식 사진 기준). 상태바는 없습니다.
    실제로 가려지는 하드웨어 영역은 우하단 카메라·플래시 홀뿐이며, 하단 72px 전체 띠는 Samsung 커버 앱 사진에서 본 하단 UI 보호 구조를 단순화한 근사치입니다(커버 화면 브라우저의 실제 레이아웃은 미확인).
- 필수 값이 빠지거나 키가 틀리면 브라우저 콘솔에 [반응형 테스트랩] 경고가 표시됩니다.
