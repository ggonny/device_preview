반응형 테스트랩

실행 방법
1. 압축을 푼 뒤 index.html을 브라우저에서 엽니다.
2. 테스트할 사이트 주소를 입력하고 ‘사이트 열기’를 누릅니다.
3. 왼쪽 기기 프리셋과 상단의 회전 버튼으로 화면을 확인합니다.
4. 브라우저 종류를 고르고 주소창·툴바 스위치로 실제 사이트 표시 영역을 비교합니다.
5. 로컬 파일 실행이 제한되면 VS Code Live Server로 폴더를 실행해 주세요.

포함 기능
- 320 / 360 / 390 / 430px 기준 모바일 프리셋
- iPhone SE·iPhone 18 Pro·Google Pixel 10 프리셋
- Galaxy Z Flip8: 커버 / 펼침 / Flex 90°
- Galaxy Z Fold8: 커버 / 펼침
- iPhone Duo: 접힘 외부 / 펼침 내부
- 가로·세로 회전, 직접 화면 너비·높이 입력 (회전·직접 입력값은 다시 열 때 복원)
- 실기기 배율 / 화면 맞춤 / 100% 보기
- 브라우저 종류 선택: Safari, Chrome (iOS), Chrome, Samsung Internet, Chrome (태블릿), Safari (iPad)
  · 기기 플랫폼에 맞는 브라우저만 목록에 나오고, 선택은 플랫폼별로 기억됩니다.
- 상태바 / 주소창 / 툴바 / 홈 인디케이터 밴드를 브라우저별 위치·높이로 표시
  · 주소창 스위치: URL 바 표시 여부 (끄면 스크롤로 숨은 상태. 상태바·홈 인디케이터는 유지)
  · 주소창 위치(상단/하단): 세로 모드에서 선택. 기본값은 브라우저별(Safari 하단, Chrome·Samsung Internet 상단)이며 선택은 브라우저별로 기억됩니다.
    상단이면 상태바(노치·다이내믹 아일랜드·펀치홀 영역) 아래에서 시작하고, 하단이면 콘텐츠 아래·툴바 위에 놓입니다.
    가로 모드에서는 실제 브라우저처럼 상단에 고정됩니다.
  · 툴바 스위치: 하단 툴바 표시 여부
  · UI 겹침 스위치: URL 바·툴바가 사이트 영역을 줄이지 않고 콘텐츠 위에 겹침 (100vh 가림 확인)
- 상단 컨트롤은 기기 정보 → 화면 상태 → 화면 크기 → 브라우저 UI → 회전·배율 순서로 자리가 고정되어 있어
  접힘/펼침 기기를 선택해도 다른 컨트롤의 위치가 바뀌지 않습니다. (단일 화면 기기는 '단일 화면' 표시)
- 다중 비교 (왼쪽 상단 '단일 보기 / 다중 비교' 스위치)
  · 기기 목록이 체크박스로 바뀌며 최대 4개까지 선택할 수 있습니다. 체크를 해제하면 해당 카드만 사라집니다.
  · 카드는 CSS Grid(auto-fit) 로 폭에 따라 1~4열에 자동 배치되고, 좁은 화면에서는 다음 줄로 내려갑니다.
  · 공통 제어(모든 카드에 적용): URL 열기, 새로고침, 회전, 주소창·툴바·UI 겹침, 주소창 위치, safe-area 가이드, 배율.
    직접 크기 입력과 브라우저 종류 선택은 단일 보기에서 사용합니다(플랫폼별 브라우저 선택은 비교 카드에도 적용).
  · 카드별 제어: 기기명·사이트 크기 표시, 화면 상태(접힘/펼침 기기), 회전, 새로고침, 비교 목록에서 제거.
  · 동기화 옵션: 스크롤 / 회전 / 새로고침. 회전·새로고침 동기화를 끄면 카드 버튼이 그 카드에만 적용됩니다.
  · 스크롤 동기화는 scrollTop 을 그대로 복사하지 않고 각 문서의 스크롤 비율(scrollTop ÷ (scrollHeight − clientHeight)) 로 맞춥니다.
    → 뷰포트 높이가 다른 기기에서도 같은 콘텐츠 위치가 보입니다. 어떤 카드를 스크롤해도 나머지가 따라오고, 추가·새로고침된 카드는 현재 위치로 정렬됩니다.
  · 선택한 기기·상태·회전·동기화 옵션은 다시 열 때 복원됩니다.

스크롤 동기화 제한 (중요)
- 브라우저의 Same-Origin Policy 때문에 iframe 안 문서의 스크롤 위치는 이 도구와 프로토콜·호스트·포트가 모두 같은 페이지에서만 읽고 옮길 수 있습니다.
  · 가능: 도구를 http://127.0.0.1:5501 로 열고 http://127.0.0.1:5501/... 페이지를 불러온 경우
  · 불가: 외부 사이트(https://example.com 등), 다른 포트, localhost ↔ 127.0.0.1 처럼 호스트 표기가 다른 경우, 도구를 file:// 로 연 경우
- 불가능한 경우 스크롤 동기화 스위치가 비활성화되고 비교 바와 카드 배지에 이유가 표시됩니다. 우회 코드는 두지 않았습니다.
- 페이지 안의 별도 스크롤 컨테이너(overflow 요소) 는 동기화 대상이 아니며, 문서(window) 스크롤만 맞춥니다.
- 향후 Chrome Extension 으로 만들면 cross-origin 페이지도 동기화할 수 있습니다:
  content script 를 all_frames 로 각 iframe 문서 안에 주입하면 그 문서의 출처에서 실행되므로 scrollTop 읽기·scrollTo 가 가능하고,
  비율 값만 chrome.runtime 메시지로 도구 페이지(또는 background) 를 거쳐 다른 프레임의 content script 로 전달하면 됩니다.
  현재 app.js 의 getScrollRatio()/applyScrollRatio()/broadcastScroll() 이 그대로 content script 로 옮겨질 수 있는 구조입니다.

상태바·컷아웃·브라우저 UI 레이어
- 노치 / 다이내믹 아일랜드 / 펀치홀 = 기기 하드웨어(frameProfiles.cutout, .screen_cutout 레이어)
- 시간 / 셀룰러 / Wi-Fi / 배터리 = OS 상태바(statusBarProfiles: ios / android / generic, .band_status 레이어)
  · 프레임의 platform 으로 프로필을 고르고 frameProfiles[*].statusBar 로 항목을 덮어씁니다(예: iPhone SE 의 compact).
  · 아이콘은 자체 SVG(외부 라이브러리·제조사 이미지 없음) 이며 좌/우 정렬 컷아웃(Fold 펼침 카메라 등) 만큼 자동으로 비켜납니다.
- Safari / Chrome 주소창·툴바 = 브라우저 UI(browserProfiles, .band_url / .band_toolbar 레이어)
- safe-area 가이드: 노치·다이내믹 아일랜드·펀치홀·홈 인디케이터가 차지하는 영역을 빗금으로 표시
- 기기별 둥근 모서리, 홈 버튼, 노치, 다이내믹 아일랜드, 펀치홀, 커버 카메라, 접힘선, 홈 인디케이터 표시
- 프리셋별 전체 CSS 화면, 실제 사이트 표시 영역, 물리 해상도와 DPR 표시

배율 구분
- 실기기: 공개된 화면 크기와 CSS 화면을 기준으로 계산한 물리 크기 근사값입니다.
- 맞춤: 미리보기 영역 안에 기기 전체가 들어오도록 자동 축소합니다.
- 100%: CSS 1px을 PC 브라우저의 CSS 1px로 표시합니다.
- 실기기 배율은 모니터 크기와 Windows 화면 배율에 따라 실제 기기 크기와 차이가 날 수 있습니다.

사이트 영역 계산
- 프리셋의 너비·높이는 기기 전체 CSS 화면입니다.
- 기본(축소) 모드: 상태바 + 주소창 + 툴바 + 홈 인디케이터 높이를 뺀 영역이 iframe 크기가 됩니다.
  → 실기기에서 브라우저 UI가 모두 보이는 상태(svh)에 해당합니다.
- UI 겹침 모드: 상태바·홈 인디케이터만 빼고 주소창·툴바는 콘텐츠 위에 겹칩니다.
  → 실기기에서 100vh가 큰 뷰포트(lvh) 기준으로 잡혀 하단 고정 요소가 URL 바에 가려지는 현상을 확인할 수 있습니다.
- 가로 모드에서 iOS Safari·Android Chrome은 컷아웃 쪽 safe-area만큼 사이트 폭이 줄어듭니다(기본 동작). 미리보기도 같은 폭으로 계산합니다.

확인 범위
- 브라우저 UI 높이는 Safari·Chrome·Samsung Internet의 일반적인 값을 바탕으로 한 근사치이며, 스크롤에 따른 자동 숨김은 구현하지 않습니다.
- 검은 노치·카메라·접힘선과 safe-area 가이드는 콘텐츠 위에 표시되어 가려지는 영역을 확인할 수 있습니다.
- iframe 안의 페이지는 env(safe-area-inset-*) 값을 받을 수 없습니다. 가이드와 겹치는 콘텐츠는 실기기에서 가려질 수 있습니다.
- 표시된 물리 해상도와 DPR은 기기 사양 정보이며 iframe의 실제 렌더링 DPR과 UA를 변경하지는 않습니다.
- 프레임과 가림 위치는 제조사 공개 사양을 바탕으로 한 시각적 근사치입니다.
- iframe에서 재현되지 않는 것: UA, 실제 DPR, 터치·hover·pointer 미디어, safe-area 환경변수, dvh/svh/lvh 단위, 대상 페이지의 <meta name="viewport"> 처리(비반응형 페이지가 980px로 축소되지 않음), 가상 키보드, 브라우저 자동 숨김, 실제 힌지·화면 분할 API.
- Windows 브라우저에서는 iframe 안에 데스크톱 스크롤바(약 17px)가 생겨 콘텐츠 폭이 줄어들 수 있습니다.
- 대상 사이트가 X-Frame-Options 또는 CSP frame-ancestors로 iframe 표시를 차단하면 미리보기가 비어 보일 수 있습니다.

기기 추가 방법 (app.js)
- devices 에 항목을 추가하면 사이드바·기기 수·WebMCP 도구 목록에 자동 반영됩니다.
  · group: deviceGroups 의 id (base / phone / fold / tablet)
  · frame: frameProfiles 의 키, browser: browserProfiles 의 키
  · states[]: width/height(CSS px), diagonal(inch), physicalWidth/Height(생략 시 width×dpr), 필요하면 frame/browser/hinge/orientation 오버라이드
- 새 컷아웃·safe-area가 필요하면 frameProfiles 에 프로필을 추가합니다. cutout.type 은 none / notch / island / hole / dual-hole.
- 필수 값이 빠지거나 키가 틀리면 브라우저 콘솔에 [반응형 테스트랩] 경고가 표시됩니다.
