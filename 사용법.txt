반응형 테스트랩

실행 방법
※ 권장 실행: VS Code 에서 이 폴더를 열고 index.html 에서 Live Server(Go Live) 로 실행합니다.
   프로젝트 설정(.vscode/settings.json) 에 따라 Device Preview 전용 Chrome 창이 overlay 스크롤바 모드로 열립니다
   (--enable-features=OverlayScrollbar, 전용 임시 프로필 — 평소 쓰는 Chrome 프로필·설정은 바뀌지 않음).
   · 이유: Windows 기본 스크롤바(약 15px) 는 미리보기 화면 안의 콘텐츠 폭을 차지해 실제 휴대폰보다 좁게 배치됩니다
     (예: 360 기기에서 콘텐츠 폭 345). 휴대폰 브라우저처럼 스크롤바가 공간을 차지하지 않게 맞추는 테스트 환경 설정이며,
     테스트하는 사이트를 수정하는 것이 아닙니다.
   · 다른 방법으로 열 때는 Chrome 을 같은 옵션으로 실행하세요:
     chrome --enable-features=OverlayScrollbar --user-data-dir=%TEMP%\device-preview-chrome
     (평소 Chrome 이 켜져 있어도 전용 프로필이라 새 창으로 열리며 옵션이 적용됩니다.)
   · 상단에 "테스트 환경 주의" 안내가 보이면 이 모드가 아닌 브라우저입니다. 안내에 표시된 폭만큼 콘텐츠가 좁게 배치되어
     실기기와 결과가 다를 수 있으니, device_preview 폴더에서 Go Live 로 다시 실행해 주세요.
1. 압축을 푼 뒤 index.html을 브라우저에서 엽니다.
2. 테스트할 사이트 주소를 입력하고 ‘사이트 열기’를 누릅니다.
   (URL 을 입력하기 전에도 주소창 아래에 선택된 기기 프레임이 바로 표시되고, 기기 선택·접힘/펼침·회전·브라우저·가이드·배율을 모두 쓸 수 있습니다. 화면 안에는 "URL을 입력해 미리보기를 시작하세요." 자리표시 페이지가 들어 있습니다.
    주소창을 비우고 "사이트 열기"(또는 입력창의 × 지우기) 를 누르면 사이트만 내리고 현재 기기 프레임은 그대로 자리표시 페이지로 돌아갑니다.)
3. 왼쪽 기기 프리셋과 상단의 회전 버튼으로 화면을 확인합니다.
4. 브라우저 종류를 고르고 주소창·툴바 스위치로 실제 사이트 표시 영역을 비교합니다.
5. 로컬 파일 실행이 제한되면 VS Code Live Server로 폴더를 실행해 주세요.

    가로 모드에서는 실제 브라우저처럼 상단에 고정됩니다.
  · 툴바 스위치: 하단 툴바 표시 여부
  · UI 겹침 스위치: URL 바·툴바가 사이트 영역을 줄이지 않고 콘텐츠 위에 겹침 (100vh 가림 확인)

    - Safari [Compact | Top]: 아이폰 설정 › 앱 › Safari › 탭 레이아웃. 기본 Compact. 주소창 위치는 이 선택을 따릅니다(Compact = 하단, Top = 상단 + 하단 툴바) — 주소창 위치 라디오는 잠깁니다.
    - viewport-fit [auto | cover]: 테스트할 사이트가 <meta name="viewport"> 에 viewport-fit=cover 를 쓰는지 알려 주는 설정. 기본 auto(지정 없음).
      가로에서 auto 는 사이트 폭 750(좌우 safe-area 제외), cover 는 874(화면 전체 — safe-area 62 는 사이트 안쪽 값) 입니다.
      iframe 안 사이트의 meta 를 바꾸는 기능이 아니라 미리보기 크기 계산 설정입니다.
    - 두 선택은 저장되어 다시 열 때 복원되며, 다른 기기·브라우저에는 영향이 없습니다.
- 상단 컨트롤은 기기 정보 → 화면 상태 → 화면 크기 → 브라우저 UI → 회전·배율 순서로 자리가 고정되어 있어
  접힘/펼침 기기를 선택해도 다른 컨트롤의 위치가 바뀌지 않습니다. (단일 화면 기기는 '단일 화면' 표시)
- 각 기기는 실제 기기의 대표 실측 상태 하나로만 표시됩니다. 기기의 화면 확대/축소(Display Zoom · 화면 크기) 단계, 글자 크기·접근성 확대,
  브라우저 확대 설정은 별도로 재현하지 않습니다(실제 기기 프리뷰이며 설정 조합 시뮬레이터가 아님).
- 다중 비교 (왼쪽 상단 '단일 보기 / 다중 비교' 스위치)
  · 기기 목록이 체크박스로 바뀌며 최대 4개까지 선택할 수 있습니다. 체크를 해제하면 해당 카드만 사라집니다.
  · 카드는 CSS Grid(auto-fit) 로 폭에 따라 1~4열에 자동 배치되고, 좁은 화면에서는 다음 줄로 내려갑니다.
  · 공통 제어(모든 카드에 적용): URL 열기, 새로고침, 회전, 주소창·툴바·UI 겹침, 주소창 위치, safe-area 가이드, 배율.
    직접 크기 입력과 브라우저 종류 선택은 단일 보기에서 사용합니다(플랫폼별 브라우저 선택은 비교 카드에도 적용).
  · 카드별 제어: 기기명·사이트 크기 표시, 화면 상태(접힘/펼침 기기), 회전, 새로고침, 비교 목록에서 제거.
  · 동기화 옵션: 스크롤 / 회전 / 새로고침. 회전·새로고침 동기화를 끄면 카드 버튼이 그 카드에만 적용됩니다.
  · 스크롤 동기화는 scrollTop 을 그대로 복사하지 않고 각 문서의 스크롤 비율(scrollTop ÷ (scrollHeight − clientHeight)) 로 맞춥니다.
    → 뷰포트 높이가 다른 기기에서도 같은 콘텐츠 위치가 보입니다. 어떤 카드를 스크롤해도 나머지가 따라오고, 추가·새로고침된 카드는 현재 위치로 정렬됩니다.
  · 선택한 기기·상태·회전·동기화 옵션은 다시 열 때 복원됩니다.

스크롤 동기화 제한 (중요)
- 브라우저의 Same-Origin Policy 때문에 iframe 안 문서의 스크롤 위치는 이 도구와 프로토콜·호스트·포트가 모두 같은 페이지에서만 읽고 옮길 수 있습니다.
  · 가능: 도구를 http://127.0.0.1:5501 로 열고 http://127.0.0.1:5501/... 페이지를 불러온 경우
  · 불가: 외부 사이트(https://example.com 등), 다른 포트, localhost ↔ 127.0.0.1 처럼 호스트 표기가 다른 경우, 도구를 file:// 로 연 경우
- 불가능한 경우 스크롤 동기화 스위치가 비활성화되고 비교 바와 카드 배지에 이유가 표시됩니다. 우회 코드는 두지 않았습니다.
- 페이지 안의 별도 스크롤 컨테이너(overflow 요소) 는 동기화 대상이 아니며, 문서(window) 스크롤만 맞춥니다.
- 향후 Chrome Extension 으로 만들면 cross-origin 페이지도 동기화할 수 있습니다:
  content script 를 all_frames 로 각 iframe 문서 안에 주입하면 그 문서의 출처에서 실행되므로 scrollTop 읽기·scrollTo 가 가능하고,
  비율 값만 chrome.runtime 메시지로 도구 페이지(또는 background) 를 거쳐 다른 프레임의 content script 로 전달하면 됩니다.
  현재 app.js 의 getScrollRatio()/applyScrollRatio()/broadcastScroll() 이 그대로 content script 로 옮겨질 수 있는 구조입니다.

표시 배율
- 배율은 기기 프레임 전체의 "보이는 크기" 만 바꿉니다. iframe 의 CSS 뷰포트, 미디어 쿼리 결과, DPR, 기기 프로필은 배율과 무관하게 그대로입니다.
- 100% = 기기 CSS 1px 을 PC 브라우저 CSS 1px 로 1:1 표시하는 배율입니다. 실제 기기의 물리 크기가 아닙니다.
- [−] / [+]: 현재 배율에서 5% 씩 줄이거나 키웁니다 (25%~200%). 숫자 칸에 % 를 직접 입력하고 Enter 하면 5% 단위로 반올림해 적용됩니다(↑/↓ 키도 5% 단위).
- 수동으로 정한 배율은 창 크기를 바꾸거나 기기를 바꾸거나 회전해도 그대로 유지됩니다.
- 화면 맞춤: 미리보기 영역에 기기 전체가 들어오도록 자동 축소하며, 창 크기·기기·회전이 바뀌면 다시 계산합니다.
- 실기기: 공개된 화면 크기(inch)와 CSS 화면으로 계산한 물리 크기 근사값입니다. 모니터 크기와 Windows 화면 배율에 따라 실제 기기 크기와 차이가 날 수 있습니다.

사이트 영역 계산
- 프리셋의 너비·높이는 기기 전체 CSS 화면입니다.
- 기본(축소) 모드: 상태바 + 주소창 + 툴바 + 홈 인디케이터 높이를 뺀 영역이 iframe 크기가 됩니다.
  → 실기기에서 브라우저 UI가 모두 보이는 상태(svh)에 해당합니다.
- UI 겹침 모드: 상태바·홈 인디케이터만 빼고 주소창·툴바는 콘텐츠 위에 겹칩니다.
  → 실기기에서 100vh가 큰 뷰포트(lvh) 기준으로 잡혀 하단 고정 요소가 URL 바에 가려지는 현상을 확인할 수 있습니다.
- 가로 모드에서 iOS Safari·Android Chrome은 컷아웃 쪽 safe-area만큼 사이트 폭이 줄어듭니다(기본 동작). 미리보기도 같은 폭으로 계산합니다.
- iPhone 18 Pro + Safari 는 위 합산 대신 iPhone 17 Pro 실기기 Safari 26.5 측정값(2026-10-12)으로 사이트 영역을 정합니다.
  화면에 그리는 Safari 주소창·툴바 높이(시각용)와 사이트 영역(CSS viewport) 은 서로 다른 값이라 따로 관리합니다 — 실측 사이트 영역은 UI 높이 합산과 맞지 않았습니다.
  · 축소 모드 = small viewport(svh), UI 겹침 = large viewport(lvh). Safari UI 는 사이트 위에 그림만 얹고 사이트 높이에서 다시 빼지 않습니다.
  · 사이트 영역(가로 × 세로):
                       축소(svh)                  UI 겹침(lvh)
      Compact · auto   402×714 / 가로 750×292     402×754 / 가로 750×402
      Compact · cover  402×714 / 가로 874×292     402×754 / 가로 874×402
      Top · auto       402×660 / 가로 750×292     402×812 / 가로 750×402
      Top · cover      402×660 / 가로 874×292     402×874 / 가로 874×402
  · UI 겹침은 lvh(100vh) 확인용이며, 실제 스크롤 중 innerHeight(dynamic: Top 세로 768 · Compact cover 세로 754 · 가로 402) 와 늘 같은 값은 아닙니다. dynamic 값은 데이터로만 보존합니다.
  · Compact · auto 세로의 dynamic 최대값은 Compact 상태 측정 기록이 없어 아직 확정하지 않았습니다.
  · safe-area 가이드: 가로 cover 는 사이트(874) 안쪽 양옆 62 를 표시하고, 가로 auto 는 사이트 폭이 이미 750 이고 실측 env 값이 0 이라 좌우 가이드를 표시하지 않습니다.
  · 주소창·툴바 스위치를 끄면 그 UI 그림만 숨기고 사이트 영역은 실측값 그대로 둡니다.
  · 17 Pro 측정을 같은 402 × 874 화면의 18 Pro 에 적용한 값(verified-derived) 입니다. iPhone SE · iPad · iPhone Duo 의 Safari 와 Chrome(iOS) 등 다른 브라우저는 기존 계산 그대로입니다.
  · Top 세로 주소창 60 · 툴바 58, 가로 상단 110 은 실측 화면 위치에 맞춘 그림이고, Compact 세로 주소창 50 · Compact 화면상 위치는 근사값입니다.

가림 검사 (단일 보기)
- 상단 오른쪽 버튼 중 safe-area 가이드 옆 "가림 검사" 버튼을 켜면 두 가지가 함께 켜집니다.
  · 위험 영역 표시: 카메라·노치·Dynamic Island(빨간 점선), 상태바·홈 인디케이터·3버튼(파란 실선), 주소창·툴바(파란 점선), safe-area(주황 점선)
  · 자동 검사: 테스트 페이지의 position: fixed 요소와 지금 화면에 붙어 있는 position: sticky 요소가 위 영역과 겹치는지 확인합니다.
- 결과는 아래 상태줄에 "가림 요소 3 · 하드웨어 1 · OS 1 · 브라우저 1 · safe-area 2" 처럼 표시되고, 겹친 요소는 미리보기에 주황 테두리로 표시됩니다.
  · 실선 = 실제로 가려지는 겹침(하드웨어·OS·브라우저), 점선 = safe-area 안에 있는 주의 상태
  · 가림 요소 수는 중복 없는 요소 개수이고, 분류별 숫자는 사유별 개수입니다(한 요소가 브라우저 UI 와 safe-area 에 함께 걸리면 둘 다 셉니다).
- 자동 검사는 이 도구와 같은 출처(프로토콜·호스트·포트가 같은) 페이지에서만 됩니다.
  다른 출처 사이트는 브라우저 보안 정책상 내부를 볼 수 없어 "자동 검사 불가 · 다른 출처" 로 표시되고, 위험 영역만 보여 줍니다(문제 없음으로 판정하지 않습니다).
- safe-area 는 주의 판정입니다. 미리보기 iframe 안의 사이트에는 실제 기기의 env(safe-area-inset-*) 값이 전달되지 않으므로, 실기기에서는 사이트가 스스로 피했을 수도 있습니다.
- 회전·기기 변경·UI 겹침·Safari 레이아웃·viewport-fit·주소창/툴바 스위치를 바꾸거나, 페이지를 새로 불러오거나, 페이지 스크롤이 멈추면 자동으로 다시 검사합니다.
  메뉴 열기·팝업처럼 페이지 내용이 바뀐 경우는 자동으로 감지하지 않으니 "다시 검사" 를 눌러 주세요.
- 같은 출처 검사 결과가 있으면 상태줄의 "결과 보기" 로 문제 요소 목록을 열 수 있습니다(번호 · 요소 이름 예: div#hdr.site_header · fixed/sticky · 겹친 영역).
  · 미리보기의 주황 테두리에도 같은 번호가 붙습니다. 목록 항목을 누르면 그 요소의 지금 위치가 파란 굵은 테두리로 약 2초간 강조됩니다(페이지는 바꾸거나 스크롤하지 않습니다).
  · 검사 뒤에 스크롤해서 위치가 바뀌었거나 sticky 가 더 이상 붙어 있지 않으면 지금 위치를 점선으로 보여 주고 "다시 검사 필요" 를 알려 줍니다. 요소가 사라졌으면 "요소가 변경됨 · 다시 검사 필요" 로 표시됩니다.
  · Esc 로 목록을 닫을 수 있습니다.
  · 요소 이름에는 태그 · id · class 만 씁니다(예: header#site_header.site_header). id 와 class 가 없으면 "div (식별자 없음)" 처럼 표시하며, 페이지 본문 글이나 입력값 · aria-label · title · placeholder 같은 내용은 목록과 리포트에 넣지 않습니다.
- "리포트 복사" 를 누르면 한 번 다시 검사한 최신 결과를 메신저·이슈에 바로 붙일 수 있는 글로 복사합니다.
  · 들어가는 내용: 페이지 주소(도메인 + 경로까지만 — ? 뒤 쿼리와 # 뒤는 넣지 않음), 기기·상태, 화면 크기·DPR, 방향, 브라우저와 주소창·툴바 상태, (iPhone 18 Pro Safari 만) Safari 레이아웃·viewport-fit, 축소 / UI 겹침, 사이트 viewport, 문제 요소(이름 · fixed/sticky · 겹친 영역 · 사이트 viewport 기준 위치), 검사 시각
  · "가림 요소 3 (실제 가림 2 · 주의 1)" — 카메라·OS·브라우저 UI 와 하나라도 겹치면 실제 가림, safe-area 에만 걸리면 주의로 셉니다.
  · 다른 출처 사이트는 환경 정보와 "자동 가림 검사: 불가 — 다른 출처" 만 복사합니다(0개로 기록하지 않음). URL 이 없거나 불러오는 중, 다중 비교에서는 버튼이 비활성입니다.
  · 입력란 값·textarea 내용·폼 데이터·페이지 본문 글·aria-label·title·placeholder 는 넣지 않습니다(요소는 태그·id·class 로만 표시).
  · 자동 복사가 막히면(예: 같은 와이파이의 다른 기기에서 http://192.168.x.x 로 열었을 때) 리포트 글을 담은 상자가 뜨니 직접 선택해 복사해 주세요.
- 요소가 아주 많은 큰 페이지는 자동 재검사를 끄고 "다시 검사" 로만 갱신합니다(검사 결과는 빠짐없이 표시).
- 다중 비교 모드에서는 쓰지 않습니다. 검사를 끄면 미리보기 화면은 이전과 똑같습니다.

확인 범위
- 브라우저 UI 높이는 Safari·Chrome·Samsung Internet의 일반적인 값을 바탕으로 한 근사치이며(iPhone 18 Pro Safari 사이트 영역은 실기기 측정값), 스크롤에 따른 자동 숨김은 구현하지 않습니다.
- 검은 노치·카메라·접힘선과 safe-area 가이드는 콘텐츠 위에 표시되어 가려지는 영역을 확인할 수 있습니다.
- iframe 안의 페이지는 env(safe-area-inset-*) 값을 받을 수 없습니다. 가이드와 겹치는 콘텐츠는 실기기에서 가려질 수 있습니다.
- 표시된 물리 해상도와 DPR은 기기 사양 정보이며 iframe의 실제 렌더링 DPR과 UA를 변경하지는 않습니다.
- 프레임과 가림 위치는 제조사 공개 사양을 바탕으로 한 시각적 근사치입니다. 기기 프레임의 좌우·상하 베젤은 화면을 기준으로 대칭이 되도록 맞춰져 있습니다(2026-10-07 보정).
- iframe에서 재현되지 않는 것: UA, 실제 DPR, 터치·hover·pointer 미디어, safe-area 환경변수, dvh/svh/lvh 단위, 대상 페이지의 <meta name="viewport"> 처리(비반응형 페이지가 980px로 축소되지 않음), 가상 키보드, 브라우저 자동 숨김, 실제 힌지·화면 분할 API.
- 스크롤바: 미리보기(iframe) 안에 열린 외부 사이트에는 Windows 기본 스크롤바(약 15~17px)가 그대로 보입니다. 브라우저 보안 정책상 바깥에서 그 문서의 스타일을 일관되게 제어할 수 없어, 현재 버전은 강제 숨김을 지원하지 않습니다(대상 사이트 자신의 CSS 에 ::-webkit-scrollbar 숨김 규칙이 있으면 그대로 숨겨집니다).
  이 도구 화면 자체(브라우저 창·기기 목록·미리보기 영역 등)의 스크롤바는 평소대로 보입니다. iframe 폭을 늘리거나 가장자리를 가리는 보정은 하지 않습니다(뷰포트 정확도 우선).
- 대상 사이트가 X-Frame-Options 또는 CSP frame-ancestors로 iframe 표시를 차단하면 미리보기가 비어 보일 수 있습니다.

기기 추가 방법 (app.js)
- devices 에 항목을 추가하면 사이드바·기기 수·WebMCP 도구 목록에 자동 반영됩니다.
  · group: deviceGroups 의 id (base / phone / fold / tablet)
  · frame: frameProfiles 의 키, browser: browserProfiles 의 키
  · states[]: width/height(CSS px), diagonal(inch), physicalWidth/Height(생략 시 width×dpr), 필요하면 frame/browser/hinge/orientation 오버라이드
- 새 컷아웃·safe-area가 필요하면 frameProfiles 에 프로필을 추가합니다. cutout.type 은 none / notch / island / hole / dual-hole.
  · 세로 위치는 top(위 가장자리 거리) 또는 bottom(아래 가장자리 거리, Flip8 커버처럼 카메라가 아래에 있을 때). 가로 모드는 반시계 회전(아래 → 오른쪽).
  · dual-hole 은 [플래시][렌즈][렌즈] 가로 상자: lens(렌즈 지름) / ring(링 두께) / lensGap / flash(플래시 지름) / flashGap. display.mask:'holes' 를 주면 디스플레이 마스크에서 렌즈·플래시 원이 빠져
    실제 가시 영역이 되고(콘텐츠가 렌즈 뒤로 가지 않음), 하드웨어(.screen_cutout) 는 마스크 바깥 레이어에 그려집니다.
- 기기 형상은 전부 frameProfiles 데이터로 정하며, 각 프로필의 source 메타데이터에 값의 근거 등급을 적습니다:
  · official       : 제조사 공개 수치 (해상도, 바디 mm, iOS safe-area 등)
  · derived        : 공개 수치에서 환산 (베젤 = (바디 − 활성영역)/2 → CSS px, 동심 가정 바디 코너 = 화면 코너 + 베젤 등)
                     같은 기기의 같은 물리 부품 실측에서 유도한 값은 verified-derived 로 적습니다
                     (예: Flip8 Flex 위쪽 패널의 위·좌우 베젤 16, 금속 테 4.5, 위쪽 모서리 38 / 20, 카메라 홀, 오른쪽 볼륨·측면 버튼 = 펼침 공식 렌더 실측 — Flex 를 정면에서 잰 값은 아님)
  · photo-measured : 렌더·캡처 실측 (파일명·비율을 note 에 기록. 예: Samsung 공식 Galaxy S25 정면 제품 렌더에서 측정한 프레임 곡률·베젤·측면 키,
                     Samsung 공식 Galaxy Z Fold8 펼침·커버 · Galaxy Z Flip8 펼침·커버 정면 렌더에서 측정한 모서리 곡률·베젤·링, Samsung 원격 실기기(RTL) 캡처에서 측정한 화면·UI 위치,
                     Apple 뉴스룸 "Apple-iPhone-Duo-display-sizes-260909.jpg", samsung.com "galaxy-z-flip8-features-colors-design.jpg"(Flip8 접힘 정면),
                     Commons 벡터 "IPhone SE (2nd generation) white vector.svg"(iPhone SE 홈 버튼·전면 디테일))
  · approximation  : 근거 없음 — 실제 사양처럼 취급하지 말 것 (Flip8 Flex 의 화면 높이 420·사이트 영역·힌지 쪽 아래 모양·접힘선·상태바, Duo 의 접힘선 굵기·Safari 시작 높이·회전 시 클러스터 위치, Android 하단 제스처 바 등)
  · controls 필드(홈 버튼·스피커·카메라·센서) 는 CSS 변수로 그려지며 가로 모드는 반시계 규칙으로 옮겨집니다.
    camera/sensor 에 edge:'right'|'left' + offset(화면 중심에서 아래 +/위 −) 을 주면 긴 변 베젤(iPad Air·Galaxy Tab 처럼 가로 카메라) 에 놓이고, inset 으로 가장자리에서 중심까지 거리를 정할 수 있습니다(셸 테두리 1px 안쪽 기준이라 화면에는 바디 외곽에서 inset + 1 위치에 그려집니다).
    cutout 에 edge:'right'|'left' + depth/length/offset 을 주면 긴 변 컷아웃(Galaxy Tab S11 Ultra 의 완만한 노치, shape:'wave') 이 되며 가로에서는 상단 중앙으로 돌아갑니다.
    keys:[{type:'volume'|'power'|'action'|'mute', edge, start, length, protrusion?}] 를 주면 family 기본 위치 대신 실측 위치에 키를 그리고(두 번째 volume 은 .key_volume_b, iPhone 액션 버튼 action 과 무음 스위치 mute 는 같은 .key_action 자리를 씁니다), port:{edge,width,height} 는 USB-C 같은 커넥터 슬롯입니다.
  · 해상도는 세 층위로 적습니다: nativePhysicalResolution(제조사 표기 그대로, official) / renderedPhysicalResolution(세로 프리뷰 기준 width×height, derived-orientation) / cssViewport(DPR 가정 파생값, derived — 해당 모델 실기기에서 innerWidth·devicePixelRatio 를 직접 확인한 경우에만 verified. 전작·동일 패널 준용값은 derived).
- 기기 형상은 전부 frameProfiles 데이터로 정합니다 (CSS 에 기기명 분기 없음):
  · family: 형상 언어. iphone-modern / iphone-classic / galaxy-bar / fold / flip / duo / ipad-classic / ipad-modern / galaxy-tab / neutral
    → 바디 마감(금속 링 색·하이라이트·글래스 색), 측면 키, 스피커·홈 버튼 표시가 이 값으로 갈립니다. 새 마감이 필요할 때만 CSS 에 family 하나를 추가합니다.
  · top/right/bottom/left: 베젤 두께(바디 외곽 ~ 디스플레이). ring: 그중 금속 테 두께, 나머지는 검은 글래스로 그려집니다.
  · radius(바디) / screenRadius(디스플레이): 숫자(px) 또는 {ratio: 0.05}(짧은 변 대비) 또는 {tl,tr,br,bl}(코너별). 가로 모드는 코너를 반시계로 돌립니다.
  · display.split: 듀얼스크린(물리 분리 패널) 용 {axis, gap, panelRadius}. 현재 프리셋에는 없음(iPhone Duo 는 단일 폴딩 화면). Surface Duo 2 같은 기기를 추가할 때 사용.
  · hingeBody: 힌지 커버(바디·디스플레이·접힘선과 별개 요소). {type:'spine', side, width, inset, radius} = 접힌 북타입에서 패널 바깥 힌지 쪽에 보이는 스파인,
    {type:'seam', size} = 펼침 상태에서 접힘선 양끝 테두리의 접합선. 가로 모드는 반시계 규칙으로 옮겨집니다(left → bottom).
  · 레이어 순서: 바디(금속 링) → 힌지 커버(.hinge_body, 바디 바깥) → 글래스 베젤 → 디스플레이 마스크(.screen_wrap: 상태바·브라우저 UI·사이트·접힘선이 모두 이 안에서 clipping) → 하드웨어 컷아웃(.screen_cutout, 마스크 바깥 셸 직계 자식).
  · Galaxy Z Flip8 커버 화면: 힌지가 위, 카메라 2개 + 플래시가 우하단에 화면 안 홀로 있습니다. 상태바는 없고, 웹 콘텐츠는 카메라 영역 위에서 끝나며
    그 아래 카메라 왼쪽에 3버튼 내비게이션이 놓입니다(실기기 화면 기준).
- 필수 값이 빠지거나 키가 틀리면 브라우저 콘솔에 [반응형 테스트랩] 경고가 표시됩니다.
